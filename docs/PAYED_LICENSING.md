# PAYED_LICENSING.md — Платный режим (внутренний документ, дизайн)

**Статус: ДИЗАЙН, НЕ реализовано.** Текущий релиз — открытый режим: полностью
бесплатно, полная функциональность, без искусственных ограничений.
Это документ для будущего переключения на платный режим — чтобы решение о
монетизации не требовало проектирования с нуля.

> Внутренний документ. Не публикуется в README/USER_GUIDE, не входит в релиз.

## 2. Цели

- Ограничить **выбранные** возможности (не «заглушить» приложение — см. §7).
- Офлайн-первое использование: программа должна работать без интернета.
- Защита от тривиального bypass, но без паранойи (данные — у пользователя,
  врага «обидеть» сложнее, чем «разозлить»).

## 3. Ключ

- **Формат:** `FNCS-XXXXX-XXXXX-XXXXX-XXXXX` (4 группы по 5, base32 без
  неоднозначных символов `0O1I`).
- **Состав:** данные лицензии (версия, срок, тип — trial/личная/бизнес) +
  HMAC-подпись ключом сервера генерации. Проверка — криптографическая,
  не «таблица ключей в клиенте».
- **Генерация:** офлайн-утилита/скрипт владельца (не входит в клиент); при
  онлайновой активации — с сервера.

## 4. Привязка к машине

- **Отпечаток:** стабильные ID (в Windows: `MachineGuid` из `HKLM\SOFTWARE\
  Microsoft\Cryptography` + серийный диска + MAC адаптера) → SHA-256 → fingerprint.
- **Толерантность:** 1 активная машина; смена fingerprint → запрос повторной
  активации (не блокировка). Для «дом + ноутбук» — тип «личная+»: 2 fingerprint.
- Fingerprint хранится в userData зашифрованным (AES-GCM, ключ — отпечаток
  самой машины), чтобы замена файла не сбрасывала привязку.

## 5. Активация и проверка

```
[main.cjs]                          [renderer]
app.whenReady
  └─ license.verify() ──┬─ open  → готово (сегодняшний путь, без изменений)
                        └─ paid  → 1. ключ? нет → экран активации
                                   2. есть → проверить подпись HMAC
                                   3. fingerprint совпадает?
                                      нет  → экран повторной активации
                                      да   → срок действует?
                                         нет (истёк) → grace 7 дней → degraded
  └─ IPC 'license:info' → licensing.ts (paid-ветка getLicenseInfo())
```

- **Онлайн-активация** (при наличии сети): POST ключа → сервер возвращает
  лицензию + срок; снижает риск «размазывать» один ключ.
- **Офлайн-активация** (базовый сценарий, обязателен): ключ активируется
  локально по HMAC — интернет не нужен.
- **Периодическая проверка:** при каждом запуске + раз в 24 ч в фоне;
  при истечении срока — 7-дневный grace (данные доступны, изменения — нет),
  далее — read-only.
- Все события — в audit log (`license.activate`, `license.renew`, `license.expire`).

## 6. Отзыв и продление

- **Онлайн:** серверный blacklist (отозванные ключи); клиент сверяет при
  проверке, если есть сеть.
- **Офлайн:** отзыв не доставляется мгновенно — принимается: ключ с истёкшим
  сроком в любом случае деградирует.
- **Продление:** новый ключ (или команда «продлить» на сервере) — старый
  fingerprint сохраняется.

## 7. Что ограничивать (решение по умолчанию — обсуждается)

**Не** делать paywall «всё приложение»: продукт — локальный, данные у
пользователя, полная блокиция = потеря доверия и обход. Рекомендация:

| Free (open-режим остаётся) | Paid |
|---|---|
| Учёт, импорт, бюджеты, валюты, периоды, профили, экспорт | Безлимитный аудит-лог (сейчас 500) |
| Холдинг: ≤ 3 юрлица, 1 уровень | Холдинг: без лимита, дерево любого уровня |
| Бэкапы авто ×5 | Бэкапы ×25 + экспорт в облако (позже) |
| | Приоритетная поддержка |

Ограничения читаются из `getLicenseInfo().restrictions[]` и применяются в
точках UI (например, блокировка создания 4-го юрлица с объяснением).

## 8. Безопасность (что реально, что нет)

- Проверка — **только в main-процессе** (renderer недоверенный: contextIsolation,
  sandbox). Результат передаётся renderer по IPC, renderer только отображает
  и блокирует UI.
- Обфускация/ASM не предполагается — защита от случайного, не от целевого
  взлома; ключевая ценность — удобство, а не DRM.
- Не хранить ключ в plaintext в userData: AES-GCM (§4).

## 9. План переключения (чек-лист)

1. `LICENSE_POLICY = 'paid'` + paid-ветка `getLicenseInfo()` (точка входа готова).
2. Модуль `electron/license.cjs`: HMAC-проверка, fingerprint, IPC `license:*`.
3. Экран активации в renderer (ключ / офлайн-файл) + read-only режим.
4. Лимиты по §7 в UI (холдинг, аудит-лог).
5. Офлайн-утилита генерации ключей (отдельный репозиторий/каталог, не в клиенте).
6. Тесты: tsx-сьют `test-licensing.ts` (HMAC, fingerprint, срок, grace, деградация).
7. Документация: USER_GUIDE «Лицензия и активация», README — paid-модель.

**Оценка (при решении делать):** 1 модуль main-процесса + 1 экран renderer +
лимиты — ~3–5 дней работы, без смены архитектуры.
