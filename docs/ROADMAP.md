# ROADMAP.md — Дорожная карта до релизного качества

> Статус: **v1.0** — составлена на основе PROJECT_ANALYSIS.md (v1.0) и полного конкурентного анализа (сегменты A, B, C, §5–§8, готов 2026-08-27). Приоритизация подтверждена анализом: must-have M1–M6 = Фазы 3–4, пересортица фаз не требуется (COMPETITOR_ANALYSIS.md §7).
> Дата: 2026-08-26.

## Принципы (из ТЗ)

1. **Стабильность и корректность финансового учёта > красивости.**
2. Обратная совместимость: существующие данные пользователей не ломаются; миграции обязательны.
3. Каждое изменение — понятный коммит; после каждого блока — обновление PROJECT_ANALYSIS.md + запись в CHANGELOG.md.
4. Тест → фикс → ретест до релизного уровня (Этап 4).

## Текущая реальность (база для roadmap)

Продукт сегодня — **аналитика по загруженным документам без памяти**: нет хранилища, сущностей учёта, периодов, мультивалютности, консолидации, лицензирования, git, тестов. Критичный баг краша в «Аналитике» и нерабочая вкладка «Активы». Это определяет фазы.

## Фаза 1 — Фундамент: хранилище и сущности учёта (критично)

Цель: превратить «аналитику по документам» в «учёт с памятью». Без этого все остальные фазы стоят.

1. **Хранилище** ✅ **Готово (2026-08-26)** — JSON-файловый стор в userData Electron, IPC `store:load/save/backups/restoreBackup/export/import` в [electron/main.cjs](../electron/main.cjs):
   - схема с версией (`schemaVersion`), атомарная запись (tmp+rename), автоматические бэкапы `.bak.1…5` + ручной экспорт/восстановление;
   - автовосстановление с бэкапа при повреждении основного файла.
   - Почему не SQLite: `nodeGypRebuild: false` в electron-builder + native-модули = хрупкие portable/NSIS-сборки; JSON-стор — читаем человеком, бэкап = копирование файла, миграции = versioned transform. (Обоснование для пересмотра — в CHANGELOG.)
2. **Сущности** ✅ **Готово (2026-08-26)** — [src/lib/store/schema.ts](../src/lib/store/schema.ts) (schemaVersion=1, uuid-ID): Организация → Счёт (банк/карта/наличные, валюта), Контрагент, Категория, Транзакция, Бюджетная цель, Период + `manual` (ручные записи «Активы»).
3. **Импорт документов в хранилище** ✅ **Готово (2026-08-26)** — кнопка «Импортировать в учёт» (левая панель Dashboard): `importDocumentToStore()` нормализует в сущности, дедупликация date+amount+контрагент+назначение (повторная загрузка того же файла — без дублей). 4. **Миграции** ✅ **Готово (2026-08-26)** — [migrations.ts](../src/lib/store/migrations.ts): `migrateStore()` — версионная цепочка, backward-compatible (v1 — стартовая версия, цепочка готова к расширению).

Smoke: [test-fx.ts](../test-fx.ts) — 38 проверок, живой ЦБ проверен (54 валюты, исторические даты). ДДС аналитики документов остаётся в ₽ (follow-up).

Эвристика «факт × 1.2» в аналитике документов (вкладка «Аналитика») осталась — отдельная поверхность по загруженному документу, замена бюджетами хранилища — follow-up.
5. **Периоды**: закрытие периода, сравнение MTD/YTD, корректирующие записи в прошлые периоды.

**Критерий:** тест-сценарии «закинул выписку банка → получил категоризированный учёт с бюджетом и прогнозом» проходят для 2+ банков. — Прогресс (2026-08-28): «выписка банка → учёт» — 4 банка + XLSX + ZIP/RAR ✅; «с бюджетом и прогнозом» — бюджеты/план-факт/прогноз/what-if готовы ✅ (3.4); остаток — 3.7 (AI-категоризация).

## Фаза 4 — Холдинг / консолидация (по ТЗ)

1. Мульти-энтити: дерево организаций, межкомпанейские операции (контрагент = юрлицо группы).
2. Консолидация: автоматический взаимоисключающий учёт (elimination intercompany), групповой баланс/OПиУ.
3. Управленческая отчётность: P&L/ДДС по статьям и центрам, бюджет/факт, коэффициенты по группе.
4. Роли и audit log (кто/когда/что изменил) — для многопользовательского сценария.

**Критерий:** тест-сценарий «2–3 юрлица, межфирменные операции, консолидированный баланс сходится» (TEST_CASES.md §холдинг).

## Фаза 6 — Релиз и публикация

1. Три артефакта: ZIP portable (автономный), portable .exe, setup .exe (NSIS с выбором папки и ярлыками).

3. Документация: README.md (актуальный, без ложных обещаний), USER_GUIDE.md, CHANGELOG.md, инструкция по активации/открытому режиму, внутренний DOC: план платного лицензирования.
4. Публикация: git push (private — ждёт подтверждения), release-тег, артефакты в GitHub Releases.
