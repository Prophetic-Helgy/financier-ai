## 1. Основное назначение и целевая аудитория

**Финансист.AI** — офлайн-десктопное приложение (Windows, Electron) для **автоматического парсинга, классификации и финансового анализа документов**: банковские выписки, ОСВ, балансы, декларации, накладные, договоры. На базе извлечённых данных строит управленческую аналитику (ОПиУ, Баланс, ДДС, коэффициенты), генерирует презентации (офлайн-шаблон или через локальную LLM — LM Studio) и экспортирует отчёты в Excel/Word/PPTX.

Заявленная лестница целевых аудиторий (через 6 профилей):

| Профиль | Аудитория | Фактический статус реализации |
|---|---|---|
| Физлицо | Личные финансы | Работает (аналитика по транзакциям) |
| Семья | Совместный бюджет | Частично (карточки с декларативными советами) |
| Самозанятый / ИП | НПД/УСН | Работает (расчёты налогов, лимиты) |
| МСБ | ОСВ, РСБУ, кэшфлоу | Работает (генераторы отчётов по ОСВ/транзакциям) |
| Селлер маркетплейсов | Unit-экономика WB/Ozon | Работает (вкладка «Селлер»: калькуляторы + аналитика выписок, 2026-08-28) |
| Холдинг | Консолидация МСФО | **Фасад**: декларативные карточки, консолидации как таковой нет |

**Важное расхождение (критично для стратегии):** в ТЗ на доработку продукт описывается как «система финансового учёта от домохозяйства до холдинга» (транзакционный учёт, счета, контрагенты, периоды, консолидация, бюджеты, казначейство). **Фактически** текущий продукт — это *аналитический инструмент по документам*: данные не ведутся в приложении, а извлекаются из файлов «на лету», не хранятся и не накапливаются. Учётной базы, журнала проводок, счёта, контрагента и периода как сущностей в коде **нет**. Это главный разрыв между видением и реализацией, который закрывается в Этапе 3 (roadmap).

## 2. Архитектура

### 2.1 Стек

| Слой | Технологии |

### 2.2 Процессная модель и поток данных

```
[Home: выбор профиля] → [Dashboard]
   │
   ├─ Импорт: FileDialog (IPC 'open-file-dialog') / Drag&Drop (IPC 'drop-files' → 'files-dropped') / web <input>
   │        → main-процесс читает файл → base64 (бинар) или UTF-8 (текст) → renderer
   │
   ├─ Архивы: expandArchives() [src/lib/parsers/archives.ts, Фаза 3.1, 2026-08-28]
   │     ZIP → fflate (рендерер, ленивый импорт); RAR → main-процесс (node-unrar-js, IPC 'archive:unrar')
   │     → файлы из архива идут в обычный parseDocument
   │
   ├─ parseDocument() [src/lib/parsers/bankParsers.ts]:
   │     PDF → pdfjs (≤50 стр.) + parseOSVFromPDF (regex по счетам)
   │     XLS/XLSX → SheetJS: сначала профили банковских выписок ([bankProfiles.ts](src/lib/parsers/bankProfiles.ts), Фаза 3.1),
   │         иначе «дата в 1-й ячейке + число во 2-й» → транзакция; label+число → метрики
   │     DOCX → mammoth; DOC → mammoth + бинарный fallback
   │     TXT/CSV → профили выписок (Сбер/Т-Банк/Альфа/ВТБ, Фаза 3.1),
   │         иначе parse1CClientBank (формат экспорта 1С:Клиент-Банк)
   │     → ParsedDocument { docType, transactions[], rawText, extractedMetrics }
   │
   ├─ Состояние: useState<ParsedDocument[]> — в памяти (сессия аналитики)
   │
   ├─ Учёт (Фаза 1, 2026-08-26): «Импортировать в учёт» → importDocumentToStore()
   │     (нормализация в сущности, дедуп date+amount+контрагент+назначение)
   │     → lib/store/store.ts → IPC 'store:save' → financier-store.json в userData
   │     (атомарная запись, авто-бэкапы ×5) → вкладка «Учёт» (LedgerView)
   │
   ├─ Аналитика (модули lib/):
   │     financialReports.ts — ОПиУ / Баланс (Ф1) / ДДС / коэффициенты / слайды / markdown
   │     profileAnalytics.ts — карточки по профилям (personal/family/msb/holding)
   │     selfEmployed.ts, sellerCalculators.ts, marketplaceAnalytics.ts
   │     analyticsEngine.ts — эвристический анализ и офлайн-презентация (Markdown)
   │     cbrService.ts — курсы/крипта/индексы/ключевая ставка (внешние API)
   │
   ├─ LLM: llmIntegration.ts — detect (127.0.0.1:1234), chat, SSE-stream, промпты (CFO-аналитика, питч-дек)
   │
   └─ Экспорт: ExportReports.tsx → CSV/TXT/HTML/JSON (собственные Blob) + XLSX/DOCX/PPTX (lib/export.ts: xlsx/docx/pptxgenjs, ленивый импорт) → скачивание
```

### 2.4 Модель данных (как есть в коде)

```ts
// Сущности документов (результат парсинга):
interface ParsedTransaction { date, amount, payer, payee, purpose, type: 'income'|'expense', account }
interface ParsedDocument   { docType: 'transactions'|'osv'|'balance_sheet'|'invoice'|'contract'|'unknown',
                             transactions[], rawText, fileName, extractedMetrics?: Record<string, number> }
// Сущности учёта (Фаза 1, [src/lib/store/schema.ts](src/lib/store/schema.ts), schemaVersion=1, uuid-ID):
Organization { id, name, isDefault }
Account      { id, orgId, name, kind: 'bank'|'card'|'cash'|'other', currency }
Counterparty { id, name }
Category     { id, name, kind: 'income'|'expense', builtin }
Transaction  { id, orgId, accountId, date, amount(>0), type, counterpartyId, category, purpose, source, importedAt }
BudgetGoal   { id, orgId, category, monthlyLimit, currency }   // под Фазу 3
Period       { id, orgId, name, closedAt }                     // под Фазу 3
// Ручной ввод (вкладка «Активы») — также персистентен: store.manual {incomes, credits, assets}
```

**Всё ещё нет**: пересчёта валют (у счёта есть currency, но вся арифметика — в ₽), закрытия периода, пользователей/ролей, audit log, холдинговой структуры. `extractedMetrics` — «словарь метрик» с неструктурированными ключами на русском (фактически плоский мешок «название→число»).

### 2.5 Хранение и безопасность данных

- Финансовые данные: **сохраняются** в JSON-хранилище (Фаза 1, 2026-08-26): файл в userData, авто-бэкапы ×5, ручной экспорт/восстановление, дедупликация при повторном импорте; ручные записи «Активы» тоже персистентны.
- localStorage: `theme`, `llm_config` (endpoint/model LLM).
- Конфиденциальность: данные не покидают машину, кроме запросов к внешним API (CBR-зеркало, Binance, corsproxy/Yahoo — [cbrService.ts](src/lib/cbrService.ts)) и LLM-endpoint (обычно локальный). Для «полного офлайна» внешние зависимости — деградация, не катастрофа (есть fallback-значения).
- В репозитории: реальные клиентские документы в `ref_data/` и `src/components/ref_data_extracted/` (119 файлов) + архивы `financier.ai.rar` (267 МБ), `financier.ai.rar`/`финансист.rar` (215 МБ), `src/components/ref_data.rar`. **Перед публикацией в git это необходимо исключить из истории** (см. Этап 5).
- Electron: contextIsolation ✅, nodeIntegration=false ✅, sandbox=true ✅, CSP ✅ (production-сборка, 2026-08-26).

### 2.6 Лицензирование / демо-режим

- Механизма лицензирования **нет вовсе**. Никакой активации, trial, key-файла.
- «Portable-режим»: `build-portable.ts` генерирует `public/portable-config.json` с заглушкой endpoint, но **приложение этот файл не читает**; `isPortableMode()` ([llmIntegration.ts:17](src/lib/llmIntegration.ts#L17)) экспортируется, но нигде не вызывается (мёртвый код). Де-факто portable-сборка = обычная сборка.
- Демо: [MockDashboardView](src/components/MockDashboardView.tsx) — статичная демонстрационная панель с mock-данными при отсутствии файлов (это маркетинговая витрина, не демо-режим с ограничениями).

### 2.7 Сборка и дистрибуция

- `npm run electron:build:installer` → NSIS Setup (oneClick=false, выбор папки, ярлыки на рабочий стол и меню пуск).
- `npm run electron:build:portable` → portable .exe.
- В `release/` уже лежат сборки от 24.04.2026 (Setup + portable, по ~107 МБ).
- Node 24 / npm 11 — OK. Vite-сборка: ~11 с. Code-splitting готов (2026-08-27): главный чанк 570 КБ (gzip 165 КБ) + ленивые RichAnalyticsReport/recharts 505 КБ, xlsx 430 КБ, export 622 КБ, pdf 329 КБ, jszip 97 КБ; pdf.worker 1.09 МБ — отдельный ассет (грузится в worker-потоке).
- ⚠️ `.gitignore` игнорирует `build/`, а в `build/icon.ico` лежит иконка, **необходимая для сборки** (package.json `win.icon`, `extraResources`). В чистом клона иконки не будет → сборка сломается.

## 5. Сильные стороны

1. **Быстрый «wow-эффект»**: бросил папку документов → получил дашборд, графики, OПиУ/ДДС/коэффициенты, презентацию. Никто в нише не даёт этого одним движением.
2. **Локальность и приватность** — все данные на машине; LLM локальная (LM Studio). Ценно для юристов/бухгалтеров с НDA и для банковских клиентов.
3. **Широкий вход: 50+ форматов** — реальный опыт обработки «грязных» клиентских архивов (тесты на 46K файлов в тест-скриптах).
4. **Чистая архитектура парсинга**: `ParsedDocument` — единый контракт; модули аналитики не зависят от источника.
5. **Профильная адаптация** — одна кодовая база под 6 сегментов; хороший каркас для расширения.
6. **Готовая дистрибуция** — electron-builder настроен (NSIS + portable), иконки, ярлыки; сборки уже собирались.
7. **Русскоязычная предметная область** — счета РСБУ, 1С:Клиент-Банк, КУДиР, НПД/УСН — редкость среди зарубежных инструментов.
8. **ИИ без облака** — LM Studio + стриминг + автообнаружение; «АИ-отчёт» офлайн.
