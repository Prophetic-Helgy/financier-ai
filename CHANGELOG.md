### Added (2026-08-29, Фаза 3.2 — OCR для скан-PDF)
- **Сканированные выписки теперь разбираются** (ранее 0% на сканах): PDF без текстового слоя — движок распознаёт текст OCR и передаёт его в обычные парсеры (`parseOSVFromPDF`, банковские профили) — «скан → учёт» работает так же, как для нативного PDF. OCR вызывается только для страниц без текстового слоя (послойная эвристика `looksLikeScan`), до 10 страниц на документ, растеризация scale 2.
- **Новый модуль [ocr.ts](src/lib/ocr/ocr.ts)** (tesseract.js v7, язык rus): ленивый синглтон-worker — wasm-ядро и языковая модель скачиваются с jsdelivr при первом запуске, дальше работает кэш браузера; без интернета OCR недоступен (PDF с текстовым слоем это не затрагивает). Статусы — в LogViewer (`[OCR] loading tesseract core`, …, `recognizing text`). В Node-окружении (tsx-тесты) OCR не вызывается (нет DOM) — E2E-распознавание проверяется PNG-буфером.
- **UI**: `ParsedDocument.ocrUsed` — маркер «OCR» у файла в списке файлов дашборда (title: «Скан: текст извлечён через OCR (tesseract.js, рус)»).
- **Бандл**: tesseract.js — ленивый чанк 15.7 КБ, подгружается только при первом OCR-вызове (проверено по графу чанков сборки); основной чанк приложения не вырос.
- **Smoke-тест** [test-ocr.ts](test-ocr.ts) (`npx tsx test-ocr.ts`): 9 проверок — `looksLikeScan` (граница 19/20 символов, реальный текстовый слой), `canOcr` в Node = false, E2E: SVG (кириллица + дата + сумма) → PNG (sharp) → tesseract rus — «Сбербанк», 15.03.2026, 1200.50 распознаны (100% на чистом тексте); при недоступности сети (не скачать модель) — SKIP без провала сьюта.
- **End-to-end в браузере** (vite dev): скан-PDF (JPEG-страница, без текстового слоя) → `parseDocument` → `ocrUsed: true`, rawText = «Сбербанк\n15.03.2026 1200.50».

### Added (2026-08-28, Фаза 3.6 — семейный сценарий: локальные профили и роли)
- **Локальные профили** ([roles.ts](src/lib/store/roles.ts), сущность `UserProfile` в схеме): в «Учёте» — секция «Профили (кто видит что)»: переключение активного профиля (выпадающий список + бейдж роли) и управление для владельца — добавление профиля (имя + роль), смена роли, удаление (кроме владельца и текущего активного), настройка видимости категорий по профилю (чекбоксы; пустой список = видит всё). Профили локальные (без аккаунтов и паролей) — для совместного использования одним компьютером семьёй/партнёрами.
- **Три роли** (матрица прав `can()`): **владелец** (admin) — полный доступ; **участник** (member) — всё кроме закрытия/открытия периодов, корректировок и восстановления из бэкапов; **наблюдатель** (viewer) — только просмотр (импорт, бюджеты, счета, курсы, категории, категоризация, бэкапы — недоступны). Кнопка «Импортировать в учёт» в левой панели блокируется для ролей без права импорта.
- **Видимость операций** (`visibleTransactions` / `canSeeCategory`): у не-владельца с непустым списком категорий видны только операции по выбранным категориям (без учёта регистра) — все итоги (статкарты, «По месяцам», MTD/YTD, бюджеты план-факт, прогноз, «По месяцам», таблица периодов, журнал) считаются по видимому срезу. Эвристика и ИИ-категоризация работают только над видимыми «Без категории».

Данные пользователей не меняются.

### Added (2026-08-29, Фаза 4 — холдинг / консолидация)
- **Мульти-энтити: дерево юрлиц группы** (схема **v3 → v4**, миграция в [migrations.ts](src/lib/store/migrations.ts)): `Organization.parentId` (головная → дочерние, глубина без ограничений) и `Counterparty.orgId` (контрагент = юрлицо группы → операция межфирменная). Секция **«Организации (группа)»** во вкладке «Учёт»: добавление юрлица (с родителем), смена родителя (без циклов — `orgParentOptions` исключает само юрлицо и его потомков), удаление (запрещено: основное юрлицо, юрлицо со счетами/операциями; при удалении контрагенты отвязываются). Доступно **только владельцу** — новая роль-право `organizations` (member/viewer — нет, [roles.ts](src/lib/store/roles.ts)).
- **Консолидация с элиминированием межфирменных операций** ([consolidation.ts](src/lib/store/consolidation.ts)):
  - межфирменная операция = операция, чей контрагент привязан к другому существующему юрлицу группы; все суммы пересчитываются в базовую (RUB) по курсу на дату (Фаза 3.3);
  - **групповой P&L**: межфирменные операции исключаются из итога группы (это не поток группы); по каждому юрлицу — доходы/расходы/итог + строка «Межфирм.»;
  - **elimination**: расход A→B и встречный доход сопоставляются в пары по ключу «направление | дата | сумма | валюта» (мультимножественный min — 2+1 = 1 пара + 1 непогашенная); непогашенные операции — явный янтарный флаг «книги юрлиц не сходятся» (без скрытого выбора стороны);
  - **инвариант**: `group.net === Σ org nets` выполняется, когда непогашенных нет — проверяется автоматически (`consolidationBalanced`).
- **Секция «Консолидация (группа, в RUB)»** (видна при >1 юрлице): таблица по юрлицам + строка «Группа (после элиминирования)», счётчик «Погашено пар: N на X ₽», фильтр по периоду, статус сходимости (зелёный/янтарный).
- **Audit log** ([audit.ts](src/lib/store/audit.ts)): `LedgerStore.auditLog` — кто (профиль), когда (ISO), что (`action`/`entity`/`detail` ≤200 симв.), хвост 500 записей; запись во всех точках персистентности: операции (в т.ч. импорт — «N файл(а), новых операций: M»), счета, бюджеты, периоды, курсы, категории, профили, структура группы, **восстановление из бэкапа**. Секция **«Журнал аудита»** (последние 30, имя профиля с фолбэком «(профиль удалён)»).
- **Селектор счёта при импорте**: при >1 юрлице имя юрлица добавляется к каждой опции счёта.
- **Smoke-тест** [test-consolidation.ts](test-consolidation.ts) (`npx tsx test-consolidation.ts`): 51 проверка — миграция v3→v4 (включая цепочку v1→v4) + идемпотентность; дерево (потомки 2 уровня, опции родителя, защита от циклов, `canDeleteOrg`); определение межфирменного (своё юрлицо/несуществующее orgId — не межфирм.); базовый сценарий 2 юрлица (группа 4600 ₽ = 4000+600, пара 1×1000, **инвариант сходимости**, ym-фильтры); непогашенная 500 → `balanced.ok=false`, группа не меняется; края (разные даты, кратность 2+1, USD@90, 1000 vs 999.99); роли; audit (поля, профиль, cap 500, clamp 200, валидация битых записей).
