## BUG-001 — Некорректные даты импортировались в хранилище ✅ (Фаза 5, 2026-08-29)

- **Статус:** исправлен, регресс-тест на месте.
- **Область:** `src/lib/store/store.ts` → `importDocumentToStore` / `normalizeDate`.
- **Симптом:** операции с пустой, мусорной или календарно-несуществующей датой (`''`, `2026-13-45`, `2026-02-30`, `гарабаз`) записывались в store «как есть». `normalizeDate` прокидывал неразбираемое значение неизменным; `ymOf` строил из них битые месячные ключи (`2026-13`, `2026-26-02` и т.п.) — такие операции выпадали из всех месячных срезов и искажали «По месяцам».
- **Воспроизведение (до фикса):**
  ```
  npx tsx -e "import('./src/lib/store/store').then(m=>console.log(JSON.stringify(m.normalizeDate('2026-13-45'))))"
  → "2026-13-45" (должно было отклоняться)
  ```
- **Причина:** валидация даты отсутствовала — проверка была только на сумму.
- **Фикс:** новая экспортная `isValidISODate()` (формат + реальное число дней месяца, високосные корректны) и `if (!isValidISODate(date)) { skipped++; continue; }` в цикле импорта. Некорректные даты теперь попадают в `ImportResult.skipped` и не пишутся в хранилище. Поведение валидных форматов (ISO, `dd.mm.yyyy`) не изменилось.
- **Регресс:** test-edge-cases.ts блок [2] (6 проверок isValidISODate + 4 битые даты → `skipped`, 2 валидные → `added`), в том числе високосные 29.02.2024 ✓ / 29.02.2026 ✗. Полная регрессия 9 сьютов — 262/262.
- **Миграция данных:** не требуется — валидных записей не трогает; в хранилищах пользователей до этого фикса могли находиться битые даты (раритет: для этого нужен файл выписки с такими датами). При необходимости такие строки видны в журнале «Учёт» и не попадают в месячные итоги.

## Тотальный пентест 2026-08-30 — принятые риски и follow-up

Находки #1–#11 закрыты кодом (см. коммит пентест-блока и `test-security.ts`, 70 проверок).
Осознанно **оставлены** как принято-документировано:

1. **API-ключ / endpoint LLM в localStorage в открытом виде.** Локальный десктоп без
   мультипользовательского секрета: процесс того же пользователя читал бы и базу
   учёта. Шифрование «ключом на той же машине» — security theater. Приемлемо.
2. **CDN-ассеты tesseract (jsdelivr) без SRI/localization.** Версии worker/core/lang
   закрепляются версией УСТАНОВЛЕННОГО пакета tesseract.js@7 (дефолтные пути выводятся
   из package.json-версии), ручная блокировка SRI/integrity и локализация ассетов —
   follow-up (пентест находка #8).
3. **`connect-src` пропускает `http:`/`https:`** — LAN-эндпоинты LLM (LM Studio на
   `192.168.x.x` http) — поддерживаемая функциональность. Экзфильтрация компенсируется lockdown'ом
   `script-src`, `validateEndpoint` (SSRF-гейт) и lockdown'ом навигации.
4. **`test-stream.ts` / `test-real-files.ts` — dev-стресс-инструменты** (сканируют
   десятки тысяч локальных файлов, при полном дереве падают по OOM). В релизный сьют
   не входят; удаление — частью скраба v1.0.1.
5. **Юнит-тесты main-процесса** (`classifyNavigation`, `validateBackupShape`) проверяют
   чистые функции; интеграционный IPC-прогон в Electron — только ручной smoke при
   установке.
6. **zip с врущим заголовком**: inflate бросает → архив остаётся в списке как
   «неизвестный документ» (fail-open на уровне пользователя, OOM невозможен).
7. **RAR**: сбой `list()` — предупреждение, бюджеты перепроверяются ПОСЛЕ распаковки.
8. **История git** содержит тексты коммитов с упоминанием «клиентским данным» — по
   решению пользователя история НЕ переписывается (фильтровали только HEAD/содержимое релиза).
